# Сравнение Git и SVN

## 1. Почему в Git ветвление "дешёвое", а в SVN — "дорогое"?

В Git ветка — это просто лёгкий указатель (файл весом ~40 байт) на определённый коммит. Создание новой ветки происходит мгновенно, так как не копируются никакие файлы. В SVN же ветвление реализовано через копирование всей директории проекта на сервере. Чем больше проект, тем дольше и ресурсоёмче эта операция, что делает ветвление "дорогим" и медленным.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, нельзя. SVN — это централизованная система контроля версий (CVCS). Вся история изменений хранится только на центральном сервере. Для выполнения операции `commit` необходимо прямое сетевое соединение с этим сервером. В отличие от Git, где у каждого разработчика есть полная локальная копия репозитория со всей историей, позволяющая коммитить офлайн.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

SVN может быть актуален в legacy-проектах госсектора и банков, где инфраструктура уже построена вокруг него и миграция слишком рискованна. Также SVN иногда выбирают для проектов с огромными бинарными файлами (арты, медиа), так как его модель работы с файлами проще для новичков, а управление правами доступа к отдельным папкам реализовано нативно и более гибко, чем в Git.
